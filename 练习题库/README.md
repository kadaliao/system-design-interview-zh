# 练习题库

iOS 学习 App（[`iOS/`](../iOS/README.md)）的闯关练习题。每章一个 JSON 文件（`04.json` 对应第 4 章），题目全部依据本仓库的中文学习版正文和第 29 章参考答案编写。App 构建时由 `工具/build_app_content.py` 校验并打包，题库本身不依赖 App，也可以给网页练习复用。

```bash
python3 工具/build_app_content.py --check          # 只校验全部题库
python3 工具/build_app_content.py --check 04 05    # 只校验指定章节
python3 工具/build_app_content.py                  # 校验并生成 App 内容包
```

## 文件结构

```json
{
  "chapter": 4,
  "keyPoints": [
    "限流要先回答三件事：限谁、限多少、超了怎么办。",
    "……"
  ],
  "lessons": [
    {
      "id": "c04-01",
      "title": "限流放哪里",
      "summary": "前端、服务端、网关各自能挡住什么",
      "exercises": [ { "id": "c04-01-01", "type": "single", "...": "..." } ]
    }
  ]
}
```

- `keyPoints`：4～6 条本章要点，App 的「单元指南」里展示。每条 1～2 句、不超过 70 字，写结论和取舍，不写“本章介绍了……”。
- `lessons`：每章 3～4 课，按正文顺序由浅入深；最后一课可以是综合场景题。每课 8～10 题。
- `title` 不超过 8 个字；`summary` 不超过 24 个字，说清这一课练什么。

## 编号规则

课 `c{章两位}-{课两位}`，题 `c{章两位}-{课两位}-{题两位}`，例如 `c04-02-07`。编号是学习进度和错题记录的主键：**已发布的题目改写内容时保留编号；删除的编号不再复用；新增题目接着往后编号。**

## 题型

所有题目都有 `id`、`type`、`prompt`、`explanation`，建议写 `ref`（出处小节标题，见下文）。App 会打乱选项、配对和排序项的显示顺序，作者按自然顺序写即可。

| type | 用途 | 专有字段 |
|---|---|---|
| `single` | 单选：概念辨析、场景判断、数字估算 | `options`（3～4 个），`answer`（正确项下标，从 0 开始） |
| `multi` | 多选：“哪些做法能……” | `options`（4～5 个），`answers`（2～3 个下标） |
| `judge` | 判断对错：常见误区 | `prompt` 写成一个陈述句，`answer` 为 `true`/`false` |
| `fill` | 选词填空：关键术语、参数、数字 | `text` 中用 `[[答案]]` 标出 1～3 个空；`distractors` 给 2～4 个干扰词 |
| `order` | 排序：请求链路、故障处理步骤、面试流程 | `items`：按**正确顺序**列出 3～6 项 |
| `match` | 连线配对：术语↔作用、方案↔代价 | `pairs`：4～5 组 `[左, 右]` |

示例：

```json
{"id":"c04-02-03","type":"single","prompt":"桶容量 B=20、补充速率 r=5 个/秒，初始满桶。同一瞬间来了 25 个请求，能放行几个？","options":["5 个","20 个","25 个","0 个，需先等待补充"],"answer":1,"explanation":"桶里最多攒 20 个令牌，同一瞬间只能花掉这 20 个；第 21 个起要等补充。速率 r 管的是长期平均，不是瞬时上限。","ref":"1. 令牌桶（Token Bucket）"}
{"id":"c04-02-04","type":"judge","prompt":"固定窗口计数器限制“每分钟 100 次”，就等于任意连续 60 秒内最多 100 次。","answer":false,"explanation":"窗口切换时计数清零，12:00:59.9 和 12:01:00.1 两侧各 100 次都合规，0.2 秒内却放行了 200 次。","ref":"3. 固定窗口计数（Fixed Window Counter）"}
{"id":"c04-02-05","type":"fill","prompt":"补全令牌桶的两个参数","text":"[[桶容量]] 决定能攒多少突发，[[补充速率]] 决定长期平均放行多快。","distractors":["窗口长度","队列长度","重试次数"],"explanation":"“桶有多大决定能冲多猛，水流多快决定能跑多久。”","ref":"1. 令牌桶（Token Bucket）"}
{"id":"c04-03-02","type":"order","prompt":"把 Redis Lua 脚本里一次限流判断的步骤排好顺序","items":["读取当前令牌数和上次时间","按经过的时间补充令牌","判断令牌是否足够","扣减并写回状态"],"explanation":"读—补—判—扣必须在同一个原子脚本里完成，否则两台网关会同时花掉最后一个名额。","ref":"分布式环境（Distributed Environments）"}
{"id":"c04-01-06","type":"match","prompt":"把部署位置和它的特点连起来","pairs":[["客户端","可被绕过，只改善体验"],["服务端","控制力强，最可靠"],["API 网关","统一接入，便于集成"]],"explanation":"……"}
```

`match` 至少 4 组（上例仅为示意）。`fill` 的 `prompt` 是一句简短指令；答案和干扰词都是可点选的词块，彼此不能重复。

## 长度限制（手机一屏能放下）

| 字段 | 上限 |
|---|---|
| `prompt` | 120 字（带场景的单选可到 160 字） |
| `options` 每项 | 40 字 |
| `fill` 的 `text` | 90 字；每个答案/干扰词不超过 12 字 |
| `order` 每项 | 26 字 |
| `match` 左侧 / 右侧 | 12 字 / 22 字 |
| `explanation` | 150 字 |

## 出题原则

1. **有据可查**：每道题都能在本章正文或第 29 章该章答案中找到依据。数字、公式、参数必须与正文一致；正文带“批注”“准确性批注”纠正原书的地方，以纠正后的说法为准，不把原书已被指出的错误当作正确答案。
2. **考理解，不考背诵**：优先考“为什么”“换个条件会怎样”“哪里会出错”“怎样取舍”。不要考图号、章节顺序、原文措辞，也不要考与系统设计无关的冷知识。
3. **单一正确答案**：单选题只能有一个站得住的答案；有前提条件的，在题干写清楚。干扰项要是常见误解或看似合理的做法，长度和语气与正确项相近；不用“以上都对/都不对”。否定问法（“不能”“错误的是”）尽量少用，用时在 `prompt` 里用 `**不能**` 加粗。
4. **判断题**：一题只判断一个论点，正确和错误的陈述各占约一半；错误陈述应当是学习者真的会犯的误解，而不是改一个字的文字游戏。
5. **讲清为什么**：`explanation` 先说正确答案为什么对，再点出最有迷惑性的错误想法错在哪；可以用正文里的记忆口诀。不要只重复答案。
6. **题型搭配**：每课至少 3 种题型；每章至少 1 道 `match`、1 道 `order`、2 道 `fill`、3 道 `judge`。单选约占一半即可，不要全是单选。
7. **每题独立**：单元测验、随机练习和错题复习会跨课打乱抽题，每道题都必须单独读得懂。不写“接上题”“上一题”，需要的条件在题干里写全。
8. **写法**：简体中文，术语第一次出现时可附英文（与正文一致）。可以用 `**粗体**` 和 `` `代码` `` 两种行内标记，不用其他 Markdown、图片或链接。数字与单位写法与正文一致（如 `1,000 QPS`、`2^30`）。

## `ref`：出处

写成题目依据的小节标题原文（去掉 `#` 号），例如 `"1. 令牌桶（Token Bucket）"`。App 里答完题可点「回看原文」跳到在线阅读版的这一节。校验脚本会检查该标题确实存在于本章；依据来自第 29 章答案时，写该答案的编号（如 `"Q04-02"`）。本章有同名标题时，第二处写成 `"标题#2"`，第三处 `"标题#3"`，依此类推。
